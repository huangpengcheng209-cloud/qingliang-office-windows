## 本次源码仓库

从上述归档提取 96 个完整修改文件、五份累计补丁、上游许可及选定构建参考文件。源码 SHA256 与冻结身份逐一对应；补丁的固定基线和应用后字节由本地 Git 对象和隔离索引验证。无需复制或修改原有工作树。

这不代表已在干净联网环境运行源码准备工具，不代表完成编译，也不代表运行了当前 GitHub 代码的程序验收。仓库内检查只覆盖文件一致性、补丁结构及来源锁定。

本次整理检查还验证了源码准备工具对未知修改、额外文件和不安全路径的拒绝行为，共 10 项检查通过，已有文件内容保留。凭据模式及个人路径检查发现的一处路径是上游原有的注释测试示例，已核对与固定上游原文一致；其余扫描未发现匹配项。静态扫描不能保证不存在所有敏感信息。

## 社区仓库自动检查（2026-10-22）

新增补丁整体 SHA256 检查，防止只改补丁内容而保留文件名时漏检。本机 Windows 从固定公开提交下载 89 个已有文件的原文，以七个新增文件由补丁创建，五份补丁应用后共 96 个文件逐一与清单一致。仅复用一份所选文件缓存，没有复制完整源代码树。

13 项自动测试覆盖未知/暂存修改、额外文件、删除文件、合法新源码、上游 URL 校验、源码与补丁篡改及不安全路径；本机通过。GitHub 的 Source checks 工作流在 Windows/Linux 上执行相同检查，具体运行结果以仓库 Actions 为准。

以上仍不包含完整九仓库准备命令、应用构建或 GUI 验收。下一阶段的顺序和交付条件见 ROADMAP.md。

## 首个可移植原生组件（2026-10-22）

`tools/build_windows.py` 自动定位 MSVC，将全部输出写入显式工作目录；未改动原应用或其构建树。本机实际编译了公开的 `windows_save_transaction.h`，14 个文件场景通过。新的 `Windows native save component` CI 作业在托管 Windows 上执行同一构建和测试；具体结果见 Actions。

独立组件不需要原机 Office 基线支持库。它使用 Windows SDK、MSVC 和系统 API，测试程序链接 MSVC 动态运行时。故障测试使用组件已有的模板测试接口注入，不是实际断电、磁盘故障或应用 GUI 验收。

构建工具额外有七项路径/工作目录保护及只读审计测试，与此前 13 项测试合计 20 项，本机通过。冻结归档的八项选定引擎输入中有三项缺失：Boost 头文件、ICU 头文件和 UnicodeConverter 导入库。旧机目录中的对应文件存在，未据此将完整构建状态标为通过。

## 已知不足

- 部分脚注、合并/嵌套表格的内容标记落页仍与完整参考存在差异。
- 历史 PPTX 异常未因后续循环通过而全部结案。
- 更多真实业务文件、跨设备、长时间混合会话和实际打印尚未充分验收。
- VLC 历史 Windows x64 补丁、静态依赖版本与实际二进制的完整对应尚未证明。
- 本仓库不是完整离线依赖闭包，未验证陌生开发者可以一键构建。
- 暂不发布安装包，不宣称稳定版或全面替代 WPS/Microsoft Office。

实际贡献或编译后应重新验证受影响路径，不能沿用不同二进制或其他平台的历史验收。
