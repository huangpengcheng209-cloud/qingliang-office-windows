从上述归档提取 96 个完整修改文件、五份累计补丁、上游许可及选定构建参考文件。源码 SHA256 与冻结身份逐一对应；补丁的固定基线和应用后字节由本地 Git 对象和隔离索引验证。无需复制或修改原有工作树。

`tools/build_windows.py` 自动定位 MSVC，将全部输出写入显式工作目录；未改动原应用或其构建树。本机实际编译了公开的 `windows_save_transaction.h`，14 个文件场景通过。新的 `Windows native save component` CI 作业在托管 Windows 上执行同一构建和测试；具体结果见 Actions。

独立组件不需要原机 Office 基线支持库。它使用 Windows SDK、MSVC 和系统 API，测试程序链接 MSVC 动态运行时。故障测试使用组件已有的模板测试接口注入，不是实际断电、磁盘故障或应用 GUI 验收。

构建工具额外有七项路径/工作目录保护及只读审计测试，与此前 13 项测试合计 20 项，本机通过。冻结归档的八项选定引擎输入中有三项缺失：Boost 头文件、ICU 头文件和 UnicodeConverter 导入库。旧机目录中的对应文件存在，未据此将完整构建状态标为通过。

## HEIF 编解码前置库（2026-10-22）

固定三个官方归档及 994 个文件，从源码编译 x265、libde265、libheif 共 152 个 C/C++ 单元；沿用上游 HEVC 静态库配置，默认使用 VS2022 和 CMake 3.x。复现上游版本适配，并单独修复 libheif 已解码 YCbCr 图像仍经 RGB 往返的问题。补丁和完整文件独立公开，原冻结 96 文件不变。
